POST /admin/polymarket/sync — 拉 PM 赛事 + 胜负平市场，落库后立即自动触发本地匹配（≈ sync+match 一步做完）。

① 拉取（fetch_upcoming_moneyline）
· 读配置 POLYMARKET_SERIES（要拉的联赛列表）+ POLYMARKET_DAYS_AHEAD（默认 7 天）
· 端点 gamma-api.polymarket.com/events/keyset，参数 closed=false（只拉未收盘，历史赛事不拉）
· 代理：POLYMARKET_PROXY > HTTPS_PROXY > 直连。国内直连被墙（ETIMEDOUT），必须走代理（本机如 127.0.0.1:10808）
· 用 endDate 把窗口收窄到未来 N 天，避免翻完整个联赛历史（曾单 series 7万+ 事件翻 700 页）；翻页上限 POLYMARKET_MAX_PAGES（默认 50）
· 时间窗 [now-2h, now+N天]：-2h 容忍刚开球还没收盘的场次
· 只保留「能解析出主客队 + 至少 1 条 moneyline 腿」的赛事；主客队优先 teams[] 的 ordering（home/away），退化用标题解析「A vs. B」
· 比赛时间优先级：markets[].gameStartTime > event.startTime > event.endDate（startDate 是上架时间，绝不能用——曾踩坑）
· moneyline（胜负平）3 条腿识别顺序：marketMetadata.opticOddsSelectionLine(home/draw/away) → question 含 draw/队名 → groupItemThreshold(0/1/2)；同 outcome 取成交量大的

② 落库（upsert）
· polymarket_events：按 slug upsert（一行=一场比赛：联赛 / 主客队 / 开球时间 / 标题）
· polymarket_markets：按 pm_market_id upsert（home/draw/away 的 price / volume / liquidity + clob_token_id_yes/no + position_id_yes/no）
· 这一步不写 match_id（留给匹配步骤）

③ 自动匹配
· sync 末尾 try 调 match_polymarket_events()，异常被 catch，匹配失败不影响已落库事件（返回里 match 字段为 None）
· 只读，不交易、不下单。只覆盖 POLYMARKET_SERIES 配置的联赛（当前=五大联赛+欧冠欧联；世界杯走专属逻辑，不经此）

POST /admin/polymarket/match — 用 DeepSeek 把 match_id IS NULL 的事件回填 match_id。只更新 polymarket_events.match_id（NULL 留空）。不重拉 API，省代理流量 + 限频额度。

设计（代码与 AI 分工）
· 代码做粗活：按联赛 + 时间窗捞出候选 matches（DeepSeek 不会写 SQL）
· DeepSeek 做细活：在候选集内挑 match_id（主依据 kickoff 时间，队名佐证）
· 代码校验兜底：只接受候选集内的 match_id，越界 / None / 非法 → 留 NULL（防幻觉）

流程（按联赛逐个跑 _match_one_league）
· 待匹配：SELECT * FROM polymarket_events WHERE series_id=? AND match_id IS NULL
· 时间窗：基于事件 kickoff 前后各扩 _POLYMATCH_CANDIDATE_MARGIN_DAYS = 3 天，作为本地 matches.match_time 的过滤范围
· 候选：matches WHERE league_id=? AND match_time 在窗内，并查队名映射
· 调 DeepSeek：用 ai_models 表活跃的 DeepSeek（无则兜底 deepseek/deepseek-v3.2），temperature=0.0，max_tokens=4096；system prompt 明确「只许用候选集里的 match_id，不要编造」
· 校验落地：遍历返回 {slug: match_id|null}，只接受候选集内整数 id → 写 match_id；None/越界/非法 → 留 NULL

映射解析
· _resolve_series_league_map() 用 config.POLYMARKET_SERIES_LEAGUE（series_id → highlightly_league_id），再按 league.season = 2026 找本地 leagues.id
· ⚠️ 此处硬编码 season=2026，将来做非 2026 赛季，这处得改

时区归一
· Highlightly match_time=北京时间(UTC+8)，Polymarket game_start_time=UTC；匹配前统一 +8h 转北京时间再比，绝不直接比两套时区

依赖 / 性质
· 依赖 DeepSeek 实时调用（走 OfoxAI 网关），需本机网络 + 密钥
· 已匹配（match_id 非 NULL）的不会再动 → 可重复跑，只补新的

返回示例
{ "total_events":12, "total_matched":10, "total_failed":2, "leagues":[{"series_id":"...","events":6,"matched":5,"failed":1}] }

相关配置项速查
POLYMARKET_SERIES：要拉的联赛 series 列表（id+name）
POLYMARKET_SERIES_LEAGUE：series_id → highlightly_league_id 映射（决定能匹配到哪些本地联赛）
POLYMARKET_DAYS_AHEAD：拉取窗口天数（默认 7）
POLYMARKET_MAX_PAGES：单 series 翻页上限（默认 50）
POLYMARKET_PROXY / HTTPS_PROXY：出网代理（必配，否则国内超时）
POLYMARKET_TEAM_ALIASES：队名别名（队名差异大时补，DeepSeek 一般能兜）
OFOXAI_API_KEY / OFOXAI_BASE_URL：DeepSeek 调用网关密钥

调度：scheduler 每天 00:30 自动跑 sync（含 match），正常不需手动；手动调 match 用于 DeepSeek 上次挂了 / 后来本地补了比赛 / 想重匹配。两者均无 body、无 query 参数、无鉴权。
