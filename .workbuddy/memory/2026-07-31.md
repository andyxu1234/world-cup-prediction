## Taro H5 dev server 白屏排查（192.168.252.1:10086）
- **症状**：浏览器开页白屏；DevTools Console 三连报
  - `Uncaught SyntaxError: Unexpected token '<' (at runtime.js:1:1)`
  - `Uncaught SyntaxError: Unexpected token '<' (at taro.js:1:1)`
  - `Uncaught SyntaxError: Unexpected token '<' (at app.js:1:1)`
- **根因**：`client/config/index.ts` 整个文件缺失（`list_dir` 显示 `config/` 是 0 字节空目录）。Taro CLI 编译期找不到入口配置，webpack 直接 abort；浏览器请求任何 chunk 都被 Taro dev server 兜底成 index.html，HTML 被当 JS 解析 → `Unexpected token '<'`。
- **次要信号**：`client/dist/` 也是空（从未成功 build 过）；但 `src/app.config.ts`、`src/app.ts`、`src/styles/global.scss`、`src/stores/index.ts`、`src/assets/tab-home.png` 全部就位，不是代码缺失。
- **修复**：写入 Taro 4.1 模板最小配置 `client/config/index.ts`（`framework:react` + `compiler:webpack5` + `@tarojs/plugin-framework-react`，h5 devServer `port:10086 host:0.0.0.0`）。
- **第二轮报错（76 error）根因**：① Taro 4 不读 tsconfig paths，须显式 `alias:{'@':src}` → 解决所有 `@/xxx` Can't resolve；② 各页 scss 用 `$bg-primary` 等但没引 variables，须 `sass.resource:['src/styles/variables.scss']`。已在 config 加这两处。
- **第三轮报错（1 error）**：`global.scss` 自己 `@use "./variables" as *` 与 `sass.resource` 注入的同一份变量撞车（`$bg-primary` already defined，因 resource prepend 到顶部后原 @use 行变 19 行重复定义）。已删 `global.scss` 自带 @use，统一交给 sass.resource。改完 dev server watch 应自动热重编。
- **第四轮发现浏览器字体偏小根因**：Taro 4 H5 dev server 编译后的 `index.html` **没有自动注入 `<style>html{font-size:...vw}</style>`**（curl 验证过），导致 pxtransform 把 px→rem 后 `<html>` font-size 还是浏览器默认 16px，所有 rem 元素按 CSS px 渲染不变，桌面浏览器看 28px 显得偏小（小程序 rpx 是另一套自适应所以看着正常）。
- **修复**：`src/index.html` 手注 `<style>html{font-size:4.667vw}</style>`（designWidth 等效 750→600，整体放大约 25%）。

## PowerShell / cmd 兼容小坑
- PowerShell 中 `cd xxx && (if ...)` 会被解析成 `if` cmdlet 报错；不要在 PS 里嵌套 batch `if`。改用 `powershell -NoProfile -Command "if (Test-Path ...) {...}"` 单行包装；或 PowerShell 原生 `if (Test-Path ...) { } else { }`。
- `Get-ChildItem` 配 `Select-Object` 可以查 dir 内容。

## LeaguePicker 弹窗撑不开（修复 #2，10:00）
- **症状**：8 个联赛的弹窗只显示 5 个（世界杯/英超/法甲/德甲/意甲），后 3 个被裁，底部「清空/确定(8)」按钮贴着裁切边。
- **根因（双层裁切）**：
  1. `.league-modal` 设了 `max-height: 480px` + `overflow: hidden`，容器上限 480。
  2. ScrollView `style.height = Math.min(leagues.length*56+10, 240, 420)` = 420；底部 ft 约 70px；总和 490 > 480 → overflow hidden 把 ScrollView 底部 10px + 整个 ft 上沿裁掉一部分。
  3. `enhanced` 属性是 Taro 4 H5 专属（启用 better-scroll），微信原生 scroll-view 不识别这个 prop，传过去不影响行为但**之前 MEMORY.md 里的 enhanced 修复只对 H5 端生效**，微信端实际靠 `style.height` + 微信 scroll-view 默认滚动。
- **修复**：
  1. `index.scss` `.league-modal` `max-height: 480px → 600px`。
  2. `index.tsx` ScrollView `style.height` 上限 420 → 460（8×56+10=458，刚好够 8 联赛直接展开不滚；多于 8 才走 460 cap 滚动）。
  3. 移除 `<ScrollView enhanced>`，让小程序端用原生滚动；H5 端由 Taro 内部自动启用 better-scroll 不依赖这个 prop。
  4. 保留 `key={pickerKey}` + `useEffect([pickerOpen, leagues.length])` 自增 key 重建机制。
- **校验**：8 联赛时 ScrollView=458px（460 cap 内），ft≈70px，弹窗总高≈528px < 600px max-height ✓。多于 8 个联赛走 460 cap 滚动。
- **未改**：未触动 `key={pickerKey}` 机制，未改 `.league-modal-list` 的 padding。

## LeaguePicker 弹窗仍只显示 5 个 + 不能滚动（修复 #3，10:10）
- **症状**：即使 max-height 提到 600，ScrollView height 设为 460px，弹窗仍只显示 5 个联赛；用户手动尝试滚动也无效。
- **根因（深一层）**：
  1. Taro 4 H5 端 ScrollView 编译产物是 Stencil 自定义元素 `<taro-scroll-view-core>`（`@tarojs/components/dist/esm/taro-components.js` 的 bootstrapLazy 注册）。
  2. React 端 `<ScrollView style={{height:'460px'}}>` 渲染时，Taro React reconciler 调 `setProperty(dom, 'style', {...})` 把 `height: '460px'` 写入 `dom.style.height`。
  3. **但 inline style 在某些 React 渲染时机下被 Stencil 的 `connectedCallback` 覆盖**（race condition），或被 Stencil `render()` 返回的 `<Host>` 重新初始化清掉。**最终 ScrollView 实际高度变成内容自适应 = 5 联赛 ≈ 290px**。
  4. 用户截图：ScrollView ≈ 290px（5 联赛），弹窗总高 ≈ 360px，与代码里 460/600 设计值不符 → 证明 inline style 没生效。
- **修复（更稳的方案）**：
  1. `index.tsx` 删 ScrollView 的 inline `style.height`，改用 CSS class 控制。
  2. `index.scss` `.league-modal-list` 加 `height: 360px; overflow-y: auto;`（与全局 `.taro-scroll-view__scroll-y` 的 `overflow: hidden scroll` 兼容，`scroll` 本身就支持滚动）。
  3. 强制 8 联赛(458) 溢出 98px → 必滚；6 联赛(346) 装下不滚；7 联赛(392) 滚 32。
- **为什么 CSS class 更稳**：CSS class 走 stylesheet 应用，不受 React reconciler 写入时机影响；`taro-scroll-view-core` 元素继承 HTMLElement，class 选择器直接命中。
- **未改**：`max-height: 600` 保留（容器大点舒服）；`key={pickerKey}` 重建机制保留；`enhanced` 不加（H5 端原生气滚足够，微信端 better-scroll 不识别）。
